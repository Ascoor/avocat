
 خطة بناء الهيكلية الرئيسية للتطبيق (Backend أولًا)
1. المبادئ الحاكمة للتطوير

Domain-first: تنظيم الكود وفق نطاقات العمل (مثل: قضايا، عملاء، جلسات، مالية) لتجنب التداخل والتكرار.

API-first: تصميم الواجهات البرمجية (API) أولًا، قبل ربطها بالواجهة الأمامية.

Secure-by-default: جعل الأمان جزءًا من كل وحدة عمل، من المصادقة إلى التفويض والتدقيق.

Event-driven حيث يلزم: استخدام Queue/Jobs للتعامل مع المهام غير المتزامنة مثل الإشعارات ومعالجة المستندات.

Observability: التأكد من أن كل العمليات الحيوية ملاحظة عبر السجلات (logs) مع تتبع للأخطاء.

2. الطبقات المعمارية المقترحة
2.1 طبقة العرض (HTTP/API Layer)

routes/api.php: ربط المسارات المناسبة على النسخة API (/api/v1/...).

Controllers: مسؤول عن التعامل مع طلبات API:

FormRequest: للتحقق من صحة المدخلات.

Services: استدعاء خدمات النطاق، وتطبيق القواعد.

Resource: العودة باستجابة موحدة لواجهة المستخدم.

2.2 طبقة التطبيق (Application Layer)

Actions/UseCases: إدارة سيناريوهات العمل مثل:

CreateCaseAction: لإنشاء قضية جديدة.

AssignLawyerToCaseAction: لتعيين محامي للقضية.

RecordInvoicePaymentAction: لتسجيل المدفوعات الخاصة بالفواتير.

2.3 طبقة النطاق (Domain Layer)

Entities: مثل Case, Client, Invoice.

Domain Services: توفير القواعد المعقدة مثل حساب الفواتير أو معالجة القضايا.

Policies: لضمان أحقية المستخدم في تنفيذ العمليات.

2.4 طبقة البنية التحتية (Infrastructure Layer)

Eloquent Models + Migrations: تنظيم النماذج مع الجداول والعمليات ذات الصلة.

Queue/Jobs/Events: إدارة العمليات الثقيلة غير المتزامنة مثل الإشعارات والتكاملات.

Integrations: التكامل مع خدمات خارجية مثل البريد الإلكتروني وSMS.

Cache: تحسين الأداء باستخدام التخزين المؤقت.

Rate Limiting: تقييد الوصول لتقليل الضغط على الواجهات البرمجية.

3. التقسيم المعياري (Module Boundaries)
3.1 Auth & Identity

تسجيل دخول/خروج: إصدار رموز المصادقة عبر Laravel Sanctum.

إدارة الجلسات والأدوار: باستخدام RBAC.

دعم الـ MFA: إمكانية إضافة مصادقة متعددة العوامل مستقبلًا.

3.2 Cases (القضايا)

إدارة القضايا: إنشاء القضايا وتعيين المحامين، ومرحلة سير القضايا (Open → In Progress → Closed).

تخزين السجل الزمني: كل حدث يخص القضية سيكون مسجلاً في قاعدة البيانات.

3.3 Sessions & Procedures

إدارة الجلسات القانونية: حفظ مواعيد الجلسات ونتائجها.

إدارة الإجراءات: ربط الإجراءات بالمحامي أو الموظف المسؤول.

3.4 Documents

رفع المستندات: تخزينها على الخوادم أو عبر سحابة مثل S3.

تصفية البيانات: إدارة الميتاداتا مثل نوع الملف، المصدر، وربطها بالقضايا.

3.5 Finance (المالية)

الفواتير والمدفوعات: إنشاء الفواتير وجداول الدفع.

تسوية المدفوعات: إدارة الإيرادات والنفقات، والتحقق من الدفعات.

3.6 Notifications (الإشعارات)

إشعارات عبر قنوات متعددة: البريد الإلكتروني، الرسائل النصية.

إشعارات مستندة إلى الأحداث: مثل إشعار قريب لموعد الجلسة.

3.7 Search & Reporting (البحث والتقارير)

استعلامات تقارير: مثل البحث في القضايا النشطة، مواعيد الجلسات.

تقارير تشغيلية: تقارير تخص القضايا الجارية والمدفوعات.

5. دورة البيانات (Data Lifecycle)

العميل يرسل طلب API.

يتم التحقق من المدخلات عبر FormRequest.

Controller يستدعي Action المناسب.

Action يطبق القواعد ويجري العمليات داخل قاعدة البيانات.

إطلاق Event عند إتمام العملية بنجاح.

Resource يعيد استجابة موحدة للـ Frontend.

العمليات الثقيلة تُدار باستخدام Job.

6. قاعدة البيانات: قواعد تأسيسية

استخدام UUID/ULID للكيانات الهامة.

إضافة فهارس للحقل الأكثر استخدامًا في البحث (مثل case_number، client_id).

Soft Deletes للكيانات الهامة (حذف غير دائم).

جداول Pivot واضحة للعلاقات المتعددة.

7. الأمان والحوكمة

Laravel Sanctum أو Passport لإدارة المصادقة.

RBAC عبر roles, permissions.

سياسات الوصول (Policy) لكل مورد رئيسي.

تدقيق العمليات الحساسة: مثل تعديل حالة القضية أو تسوية المدفوعات.

Rate Limiting على النقاط الحساسة.

8. استراتيجية التنفيذ المرحلي (Backend First Roadmap)
المرحلة 1: Foundation

إعداد Auth + Users + Roles + Permissions.

توحيد Error handling وAPI response envelope.

تجهيز Logging/Audit.

المرحلة 2: Core Legal Flow

تطوير CRUD لـ Cases, Sessions, Procedures.

ربط الأحداث الأساسية بإشعارات داخلية.

كتابة اختبارات Feature أساسية.

المرحلة 3: Documents + Finance

إنشاء أنظمة رفع المستندات والفواتير.

تطوير Jobs للعمليات غير المتزامنة مثل الإشعارات.

المرحلة 4: Integrations + Hardening

تحسين التكامل مع الأدوات الخارجية (Email, SMS).

تحسين الأداء عبر Indexing، Caching، query optimization.

اختبار E2E.

9. تعريف Done (لكل وحدة Backend)

التوثيق الجيد لـ API contracts.

اختبارات Feature أساسية.

أمان مُفعّل.

سجلات ومقاييس مراقبة كافية.

10. ما الذي يستلمه فريق الـ Frontend بعد انتهاء كل مرحلة؟

تحديث ملف Swagger/OpenAPI.

أمثلة Responses معيارية.

قائمة صلاحيات endpoint-by-endpoint.

بيئة staging مستقرة ببيانات seed.
