# هيكلية الباكند

يوثق هذا الملف بنية Backend المقترحة/الحالية لنظام إدارة مكاتب المحاماة.

## 1) المسؤوليات الأساسية

- إدارة الهوية والتفويض (AuthN/AuthZ).
- تنفيذ قواعد الأعمال القانونية والمالية.
- إدارة البيانات والعلاقات والعمليات الحساسة.
- توفير API واضحة ومستقرة للفرونت إند والموقع.

## 2) تقسيم الطبقات

- **Routes / API Layer:** تعريف المسارات وإصدار النسخ (v1, v2).
- **Controllers:** استقبال الطلبات وتوجيهها لطبقة الخدمة.
- **Actions/Services:** تطبيق قواعد العمل الفعلية.
- **Models/Repositories:** التعامل مع قاعدة البيانات.
- **Resources/Transformers:** توحيد شكل الاستجابة.
- **Jobs/Events/Listeners:** المعالجة غير المتزامنة والتكاملات.

## 3) المجالات (Domains)

- **Cases Domain:** القضايا، أنواعها، حالاتها، وربطها بالعملاء.
- **Sessions Domain:** الجلسات، المواعيد، المحاضر، النتائج.
- **Procedures Domain:** الإجراءات القانونية وسيرها الزمني.
- **Clients Domain:** بيانات العملاء، المستندات، وسجل التواصل.
- **Finance Domain:** الفواتير، المدفوعات، القيود، التقارير.
- **Identity Domain:** المستخدمون، الأدوار، الصلاحيات.

## 4) متطلبات الأمان

- استخدام Sanctum (أو Passport عند الحاجة).
- سياسات وصول دقيقة لكل مورد (Policies).
- تتبع العمليات الحساسة عبر Audit Logs.
- تقييد المعدل (Rate Limiting) لنقاط الدخول الحرجة.

## 5) قواعد الجودة

- توحيد الاستجابات والأخطاء (Response Envelope).
- اختبارات Feature للمسارات الأساسية والتفويض.
- Migrations آمنة وقابلة للتراجع.
- فهارس DB للبحث والفلترة عالية الاستخدام.

## 6) تكامل الباكند مع بقية النظام

- الفرونت إند يعتمد على API contracts ثابتة.
- الموقع العام يستهلك APIs مخصصة للعرض العام وبوابة العميل.
- الإشعارات والتكاملات الخارجية تنفذ عبر Jobs منفصلة.
